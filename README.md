# Beeline Tariff Campaign Agent

Команда TAZART · HackAlem AI. Агент планирует тарифные маркетинговые кампании для **синтетической** аудитории кейса Beeline. Он получает профиль 23 441 абонента, проводит пилоты на текущей аудитории и возвращает 1–10 кампаний с тарифом, сегментом и каналом. Цель — прирост прогнозного ARPU за вычетом затрат на контакты с учётом лимитов бюджета и охвата. Числа и результаты кейса не описывают реальных абонентов Beeline.

Официальный интерфейс — `Agent.act(env)` в `agent.py`. В обычном запуске принятие решений выполняется локально и воспроизводимо: API-ключи для работы агента, `local_eval.py` и `make_submission.py` не требуются.

## Быстрый запуск

Требуется Python 3.12. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
streamlit run app.py
```

`local_eval.py` печатает финансовый результат на **мок-модели организаторов**. В финальном зачёте эффекты будут другими, поэтому локальные суммы показывают работоспособность и устойчивость логики, а не будущий балл. `make_submission.py` создаёт `submission.csv` с фиксированным seed 42; повторный запуск должен дать тот же файл. В Streamlit нажмите «Запустить агента», чтобы увидеть пилоты, выбранные кампании, прогнозы и журнал решений. Интерфейс не показывает скрытые эффекты среды как прогноз агента.

## Как агент принимает решение

1. `campaign_engine.py` очищает историю переходов: удаляет дубли, исключает исходный ARPU ниже 100 и ограничивает экстремальное относительное изменение. Она создаёт слабые prior для переходов `current_tariff × arpu_segment × target_tariff`, дополняя отсутствующие сочетания тарифными характеристиками. Историческая доля переходов не трактуется как конверсия на предложение: таких данных нет.
2. `agent.py` выбирает разнообразные гипотезы и запускает до 12 разведочных пилотов через `env.run_pilot`, обычно в бесплатном канале push. Для части пилотов он выбирает менее ценные подгруппы внутри базового сегмента: по правилам данного симулятора относительный эффект внутри `current_tariff × arpu_segment` одинаков, а возможный денежный ущерб от отрицательного пилота меньше.
3. По наблюдаемому эффекту пилотов агент обновляет среднее и неопределённость гипотезы с дисперсией шума `0.804² / n`. При переносе результата между push, SMS и digital_ads корректно учитывается множитель канала в значении и дисперсии. До шести дополнительных SMS-пилотов подтверждают важные неопределённые гипотезы.
4. Отбор использует консервативную оценку эффекта и сравнивает каналы по приросту ARPU, стоимости контактов и доступному бюджету. Портфель строится из непересекающихся базовых сегментов. Звонки пока исключены: их цена 160 за контакт, а перенос эффекта с других каналов может ошибаться из-за насыщения конверсии.
5. `plan_validator.py` проверяет 1–10 кампаний, реальные размеры аудиторий, допустимые фильтры и тарифы, бюджет и охват **после** пилотов. Он отклоняет планы, которые официальный скорер молча обрезал бы. Если надёжно положительных кампаний нет, агент возвращает маленькую бесплатную push-кампанию с ограниченным возможным ущербом.

Пилоты входят в общий результат и лимиты. Один клиент даёт эффект только по лучшему из полученных предложений, однако повторные контакты расходуют охват и бюджет. ID участников пилота агенту не раскрываются; прогнозы по пересечениям и итоговому уникальному охвату имеют неопределённость. Официальный `risk_score` нельзя отождествлять с вероятностью убытка из модели агента.

## Файлы и данные

| Файл | Назначение |
| --- | --- |
| `agent.py` | Официальный агент и журнал решений `trace` |
| `campaign_engine.py` | Очистка истории и генерация гипотез |
| `plan_validator.py` | Строгая проверка финального плана |
| `app.py` | Локальная Streamlit-демонстрация на мок-среде |
| `local_eval.py`, `make_submission.py`, `environment.py`, `scoring_core.py` | Предоставленные организаторами интерфейс и локальная проверка |
| `customer_profile.csv`, `data/*.csv` | Синтетические данные из пакета участника |
| `submission.csv` | Воспроизводимый результат для сдачи |

Данные из ZIP участника находятся в корне и в `data/`. Не удаляйте их до окончания проверки: `mock_environment.py`, локальный оценщик и генератор submission читают эти относительные пути. Для отправки решения нужны код в командном GitHub, README и отдельная сдача на странице треков. Перед отправкой проверьте содержимое репозитория и воспроизводимость команды выше.
