# AI-оптимизатор маркетинговых кампаний

**Команда TAZART · HackAlem AI.** Локальный продукт для маркетолога: анализирует синтетическую абонентскую базу кейса Beeline, проверяет гипотезы пилотными кампаниями и рекомендует портфель тарифных предложений. Цель — увеличение ARPU за вычетом затрат на контакты с учётом лимитов бюджета и охвата. «Штаб кампаний» показывает показатели, ход анализа, карточки рекомендаций и причины отклонения альтернатив на одном экране. Числа кейса не описывают реальных абонентов или бизнес Beeline.

Официальный интерфейс — `Agent.act(env)` в `agent.py`: метод получает публичный объект среды, запускает пилоты и возвращает от 1 до 10 финальных кампаний. Каждая кампания задаёт сегмент абонентов, предлагаемый тариф и канал связи. Пилоты и финальные кампании расходуют общий бюджет до **100 000 у. е.** и общий лимит **15 000 контактов**. На одну финальную кампанию разрешено до **5 000 контактов**, пилотов — до **20**. Повторные обращения также расходуют лимит. Продукт формирует план, но не отправляет сообщения абонентам и не подключается к системам оператора. Агент работает локально и воспроизводимо; API-ключи для него не нужны.

## Технологии и зависимости

Рабочая версия проверена на **Python 3.12**. Все прямые зависимости закреплены в `requirements.txt`:

| Пакет | Версия | Назначение |
| --- | --- | --- |
| `numpy` | `2.5.3` | Численные вычисления локальной среды и оценщика. |
| `pandas` | `2.3.3` | Чтение CSV, сегментация и расчёт аудиторий. |
| `streamlit` | `1.64.0` | Локальный веб-интерфейс. |

Исходные CSV из пакета участника должны лежать в корне проекта и в каталоге `data/`: `customer_profile.csv`, `data/change_tariff.csv`, `data/dict_tariff.csv`. Сохраняйте структуру каталогов: код читает файлы по относительным путям. Для установки пакетов через `pip` может потребоваться доступ к индексу пакетов. Агент и интерфейс не вызывают внешние AI API; отдельный скрипт `check_openai.py` проверяет доступ к OpenAI без данных кейса.

## Установка и запуск

Все команды выполняйте **из корня репозитория**, где находится `agent.py`. На macOS/Linux:

```bash
python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

`python3 --version` должен показать Python 3.12.x. Если `python3` указывает на другую версию, создайте окружение командой `python3.12 -m venv .venv`. В Windows PowerShell команда активации — `.venv\Scripts\Activate.ps1`, затем используйте те же команды `python`. Откройте `http://127.0.0.1:8501`; сервер работает, пока запущена команда, и останавливается клавишами `Ctrl+C`. Если порт занят, замените номер порта и в команде, и в адресе браузера.

### Проверка основного пользовательского сценария

1. Откройте страницу **«AI-оптимизатор маркетинговых кампаний»**. Первый экран показывает рассчитанные показатели базы и доступный бюджет без предварительного нажатия кнопки.
2. В карточке **«Сформировать план кампаний»** укажите бюджет от 0 до 100 000 у. е. и нажмите **«Сформировать оптимальный план»**. Сейчас поддержана цель **«максимизация чистого финансового эффекта»**; режимы без собственной логики расчёта не предлагаются. Для каждого запуска создаётся новая локальная мок-среда с выбранным бюджетом, и агент заново проводит пилоты.
3. Просмотрите этапы работы агента: они должны отражать выполненные действия, включая формирование гипотез, наблюдения пилотов, отбор и проверку плана. Пилотные наблюдения относятся только к текущему запуску.
4. В **«Рекомендованном портфеле кампаний»** проверьте число финальных кампаний (1–10), итоговый расход **вместе с пилотами** (не выше выбранного бюджета) и контакты (не больше 15 000). Откройте карточку: сегмент, тариф, канал, размер аудитории и стоимость должны соответствовать рассчитанному плану.
5. Откройте **«Почему выбран именно этот план»** и **«Отклонённые варианты»**. Объяснения должны ссылаться на вычисленные оценки или ограничения; если подходящих вариантов для показа нет, интерфейс должен сказать об этом прямо.
6. Измените бюджет, нажмите **«Пересчитать план»** и в блоке **«Сценарный анализ»** сравните предыдущий и новый запуски. Число кампаний и расходы могут измениться, но изменение состава плана не гарантируется. Сценарное сравнение не является результатом официального зачёта. Кнопка **«Скачать текущий план»** экспортирует показанный сценарий в CSV; для официальной сдачи отдельно запускайте `make_submission.py`.

**Как читать результат:** наблюдение пилота — зашумлённый ответ локальной мок-среды; «прогноз эффекта финальных кампаний» — сумма оценок агента по выбранным кампаниям **после их стоимости, но без вклада пилотов и поправки на пересечения с ними**. Это не полученная выручка и не полный прогноз чистого результата всего запуска. `local_eval.py` выдаёт фактический результат *публичной мок-модели* по правилам скорера. В скрытом зачёте эффекты другие, поэтому ни прогноз агента, ни локальный мок-результат не являются обещанием будущего балла.

Реализованы все три слоя демонстрационного сценария: **P0** — обзор, рабочее бюджетное ограничение, запуск настоящего агента, карточки плана и объяснения; **P1** — этапы по событиям агента, отклонённые гипотезы и рассчитанные показатели; **P2** — повторный запуск при новом бюджете и сравнение двух сценариев. Внешний AI не участвует в расчёте или принятии решений. Отправка сообщений и интеграция с системами Beeline не являются частью прототипа.

### Проверка агента и подготовка файла сдачи

В новом терминале активируйте `.venv` и выполните из корня проекта:

```bash
python -m unittest -q test_plan_validator
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

Первый вызов проверяет правила финального плана. `local_eval.py` печатает пилоты, расходы и результат на **мок-модели организаторов**; его строка «Кампаний» считает пилоты **вместе с** финальными кампаниями, поэтому может быть больше 10. Серия из десяти запусков показывает чувствительность к шуму разных seed, а не будущий балл. `make_submission.py` создаёт `submission.csv` с фиксированным seed 42. Повторный запуск с тем же кодом и данными должен дать идентичный файл. Официальная точка входа на судействе остаётся `Agent.act(env)`; в скрытой среде агент может принять другие решения.

## Архитектура и принцип работы

```text
Синтетические CSV → локальная среда → кандидаты из истории и тарифов
                                → пилоты на текущей аудитории
                                → обновление оценки и неопределённости
                                → портфель по эффекту и ограничениям
                                → строгая проверка плана
                                ├→ интерфейс маркетолога
                                └→ submission.csv для сдачи
```

Интерфейс запускает того же `Agent.act(env)`, что и генератор сдачи; отдельного демонстрационного алгоритма нет. Параметр бюджета в интерфейсе ограничен диапазоном 0–100 000 у. е. и задаёт лимит **новой** локальной среды до пилотов. При нулевом бюджете платные каналы недоступны, но бесплатный push может быть допустим. Для официального файла сдачи используется стандартный бюджет среды организаторов, без настройки из интерфейса.

Алгоритм работает так:

1. `campaign_engine.py` очищает историю переходов: удаляет дубли, исключает исходный ARPU ниже 100 и ограничивает экстремальное относительное изменение. Она создаёт слабые prior для переходов `current_tariff × arpu_segment × target_tariff`, дополняя отсутствующие сочетания тарифными характеристиками. Историческая доля переходов не трактуется как конверсия на предложение: таких данных нет.
2. `agent.py` выбирает разнообразные гипотезы и запускает до 12 разведочных пилотов через `env.run_pilot`, обычно в бесплатном канале push. Для части пилотов он выбирает менее ценные подгруппы внутри базового сегмента: по правилам данного симулятора относительный эффект внутри `current_tariff × arpu_segment` одинаков, а возможный денежный ущерб от отрицательного пилота меньше.
3. По наблюдаемому эффекту пилотов агент обновляет среднее и неопределённость гипотезы с дисперсией шума `0.804² / n`. При переносе результата между push, SMS и digital_ads корректно учитывается множитель канала в значении и дисперсии. До шести дополнительных SMS-пилотов подтверждают важные неопределённые гипотезы.
4. Отбор использует консервативную оценку эффекта и сравнивает каналы по приросту ARPU, стоимости контактов и доступному бюджету. Портфель строится из непересекающихся базовых сегментов. Звонки пока исключены: их цена 160 за контакт, а перенос эффекта с других каналов может ошибаться из-за насыщения конверсии.
5. `plan_validator.py` проверяет 1–10 кампаний, реальные размеры аудиторий, допустимые фильтры и тарифы, бюджет и охват **после** пилотов. Он отклоняет планы, которые официальный скорер молча обрезал бы. Если надёжно положительных кампаний нет, агент возвращает маленькую бесплатную push-кампанию с ограниченным возможным ущербом. При шести подряд отрицательных разведочных наблюдениях он прекращает дальнейшие пилоты, чтобы не расходовать оставшийся охват на слабые гипотезы.

Пилоты входят в общий результат и лимиты. Один клиент даёт эффект только по лучшему из полученных предложений, однако повторные контакты расходуют охват и бюджет. ID участников пилота агенту не раскрываются; прогнозы по пересечениям и итоговому уникальному охвату имеют неопределённость. Официальный `risk_score` нельзя отождествлять с вероятностью убытка из модели агента.

Для отправки решения нужны код в командном GitHub, README и отдельная сдача на странице треков. Перед отправкой проверьте содержимое репозитория и воспроизводимость команды выше.

## Параметры окружения и ключи OpenAI / NVIDIA

| Параметр | Нужен для запуска? | Применение |
| --- | --- | --- |
| `OPENAI_API_KEY` | Только для `check_openai.py` | Используется отдельной проверкой доступа к OpenAI API; агент, интерфейс, локальный оценщик и генератор сдачи его не используют. |
| `NVIDIA_API_KEY` | Нет | Зарезервирован; текущие сценарии его не используют. |
| Бюджет кампаний | Да, вводится в интерфейсе | Целое число 0–100 000 у. е.; задаёт лимит новой локальной среды до пилотов. Это не переменная окружения. |
| Начальное зерно случайности | Нет | Для веб-демонстрации и `submission.csv` используется фиксированное значение 42; `local_eval.py --runs 10` запускает несколько seed. |

Единственная поддерживаемая бизнес-цель — максимизация финансового эффекта в пределах бюджета. Настройка меньшего бюджета в интерфейсе не меняет официальные правила сдачи и не записывается в `submission.csv`.

Страница наград содержит **коды активации**, а не ключи приложения. По инструкции хакатона: активируйте OpenAI API credit через личную ссылку и проверьте **Billing → Promotions → Applied promotions** в OpenAI Platform. Бонус NVIDIA активируется через Brev в **Billing → Redeem Code**; затем проверьте **Current Balance** и создайте ключ в [NVIDIA Build](https://build.nvidia.com/settings/api-keys) под тем же аккаунтом. Ключ OpenAI создаётся отдельно в [OpenAI Platform](https://platform.openai.com/api-keys). Подписка ChatGPT/Codex Pro не заменяет ключ OpenAI API.

Для отдельной проверки OpenAI API скопируйте `.env.example` в локальный `.env` и впишите **созданный API-ключ**, а не код активации. Ключ NVIDIA для этой проверки не требуется:

```dotenv
OPENAI_API_KEY=your_openai_api_key
```

`.env` игнорируется Git, `.env.example` содержит только названия переменных. На macOS/Linux ограничьте доступ командой `chmod 600 .env`. `config.require_api_key("openai")` и `config.require_api_key("nvidia")` читают ключи из среды или локального файла. NVIDIA-клиенту нужно передавать его ключ явно вместе с `config.NVIDIA_BASE_URL`, иначе совместимый SDK может взять ключ OpenAI по умолчанию.

Проверить соединение можно отдельной командой из корня проекта:

```bash
python check_openai.py
```

Она отправляет один нейтральный текстовый запрос, не читает CSV и не передаёт данные кейса. В текущем проекте тестовый вызов завершился успешно. Эта проверка не входит в работу агента, интерфейса или официальный зачёт и не влияет на расчёт кампаний.

Инструкция хакатона требует активировать доступ, но **не требует вызывать оба API в Beeline-агенте**. Разрешение организаторов на отправку данных кейса во внешние AI-сервисы сейчас не подтверждено, поэтому агент и демо не делают внешних вызовов и не передают профиль абонентов провайдерам.

Держите командный GitHub закрытым для команды и организаторов. Не помещайте ключи в код, репозиторий, презентации, логи, чаты и скриншоты. Перед публикацией проверьте изменения на секреты и ограниченные данные. При утечке сообщите организаторам, отзовите ключ и создайте новый. После мероприятия удалите временные ключи и локальные копии предоставленных данных согласно инструкции организаторов.

## Ограничения и следующие шаги

Это симулятор с синтетическими данными. История другой аудитории — только слабое начальное предположение; один пилот шумный, а 10 локальных seed меняют лишь шум мока. Нынешний портфель использует жадный поиск по стоимости бюджета и непересекающимся базовым сегментам, поэтому глобальный оптимум не гарантируется. Следующие улучшения: отдельная проверка звонков, стресс-тесты на сдвиге скрытых эффектов и более точный учёт ожидаемых пересечений пилотов.
